# Future Requirements Registry

**状态：ACTIVE REGISTRY**  
本文件记录已知未来需求，不授权开发。任何条目进入路线图前都必须重新验证价值、成本、Windows/Web 兼容性、恢复计划、维护成本与真实用户证据。

## 状态定义

- CAPTURED：已记录，未验证。
- RESEARCH：允许调研，不允许实现。
- CANDIDATE：有证据，可在版本规划中比较。
- APPROVED：用户已批准进入未来路线图，仍需具体 Task。
- REJECTED：当前不做，并保留原因。

## MVP 防膨胀规则

Registry 中的条目不能因为“以后肯定要做”而提前开发。MVP 只允许建立低成本、已知必要的扩展边界；不得提前实现未来业务逻辑、数据库字段大全、空系统或通用化框架。
