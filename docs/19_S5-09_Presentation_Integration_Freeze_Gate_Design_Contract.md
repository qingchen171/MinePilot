## 1. Purpose, provenance and evidence rules

S5-09 is one integration and certification Task over the existing single production session, presentation root and guarded Save v4 authority. Default production behavior/source change is **zero**. Reuse sufficient existing unit, guarded-session and browser regressions; add only missing cross-operation and measurable layout evidence. A newly discovered production defect stops the gate for a scoped Bug/Protocol §7.1 assessment; this contract does not authorize a silent gameplay, RNG, schema, persistence or frozen-interface change.

Every S5-09 evidence record must identify its exact test/manual step, revision and outcome, the committed and reopened facts asserted, and one of these provenance classes:

- **Production:** current shipped catalog (`level-001` only), ordinary generated Rewards, no production obstacle or L2–L5/Next content.
- **Controlled catalog:** validated test-only catalog shared by trusted projection and the real production-session execution path; never reported as shipped content.
- **Strictly validated compatibility fixture:** preloaded Save v4 snapshot accepted by the real strict reader/mapper before a guarded production-session command; one-time Reward/L4 and selected historical facts are saved-state compatibility proof, **not** proof that the current generator creates them.

Existing evidence is a reference, not a new test or mutation injection. Mark newly added integration tests separately from reused tests; label mutation **injected** only when a real failure/incorrect variant is actually induced and killed. A behavior assertion alone is not mutation evidence. Any missing or failing assertion remains open, not implicitly covered by a green unrelated suite.

## 3. Four corrected Attack boundaries

**Legal Shop chain.** G2 is four separate, guarded commits. It never treats Home return as leaving an Attempt, never treats an uncertain/rejected/stale `abandon`/`dismiss` as a proven account-only state, and never pretends a committed leave can be rolled back after a later purchase/Start failure. After any uncertainty, explicit authority reload decides the actual current state; a later action must be newly authorized by the player. Expected revision, Account, Attempt, inventory and persisted facts are asserted at every boundary.

**Benben eligibility is probabilistic.** G4 proves both deterministic outcomes of the frozen independent 3/10 rule for fixed inputs and separates that eligibility from optional defer, separate claim, temporary resource priority, F5 and terminal expiry. A validated entitlement fixture proves compatibility of a saved state, not a single naturally observed three-failure history or guaranteed eligibility.

**Objective desktop safety.** G8 fixes both viewports and measurable overflow, obstruction, focus and Board hit-coordinate checks across all named surfaces; vertical scrolling is permitted. It cannot be replaced by subjective screenshots or by narrow board-only geometry tests, and it does not imply mobile certification.

**Freeze governance.** G9 requires traceable passing facts, defect dispositions and Elio's actual hands-on approval. A design/review/test report alone cannot grant product acceptance, mark Stage 5 frozen or create the annotated tag.
