## 2. 现在的产品定位：已确认的重定向

**一句话定义：**以扫雷为底层规则，玩家亲自操纵**可爱的小动物在棋盘格内探险移动**，当前格附近雷数以**动物头顶的数字**表达；外观是高品质 Q 版、温馨冒险式轻休闲游戏，而不是网页工具或调试 Demo。

**优先级原则：**视觉完成度、界面简洁度、信息就地呈现，对第一版能否吸引玩家至关重要；不能用“功能正确／测试全绿”代替玩家体验验收。

### 2.1 已由产品经理明确确认

1. **桌面横屏先行。** 以 **1366×768** 为第一版兼容设计基准；应合理缩放并适配 1280×720、1024×768、1920×1080 等桌面环境，不是固定画布裁切。未来增加**独立手机竖屏信息布局与触控排布**；横屏桌面与竖屏手机共用玩法权威而非两套状态系统。
2. **AI 高质量占位美术可用。** 第一版允许 AI 资产，但必须保持角色、场景、UI、道具、音效的统一美术语言；生成一张漂亮概念图不等于已获得可交互、可分层、可缩放的游戏资产。
3. **核心玩法合同大体不变。** 不变更踩雷、胜利、雷数、道具、存档与经济规则；需要重做的是游戏世界中这些规则的**视觉表达和交互呈现**。
4. **角色在格子内，数字在头顶。** 角色不是棋盘边上的宣传吉祥物。显示的应是**角色当前位置的八邻域雷数**；离开该格后旧数字不常驻。0 与已揭示雷占位遵守冻结规则。角色姿态是“探险行动”，包含移动、停下、观察等轻量动画。
5. **第一版中文优先。** 主界面角落必须**显式保留语言入口**。完整英文翻译与真实双语布局可分后续阶段；未完成前不得提供貌似可切换却不起作用的假控件，应明示当前可用语言和英语待开放状态。最终中英切换是已确定目标，不能遗忘。
6. **第一轮优先完成首页、关卡选择、游戏三大界面。** Shop、Settings 同时获得一致的基础视觉，但**二级界面的同等级精细化明确登记为下一轮待办**，不可用“已统一风格”注销这项任务。
7. **动物种类暂不固定。** 可以不是参考图中的猫/鼠/狗；必须有可爱的 Q 版探险者、动作清晰、与界面风格一致。

### 2.2 视觉交互必须达到的行为

- 棋盘应成为横屏视觉中心，界面尽可能贴近可用浏览器视口；不能再把 9×9 棋盘缩成小框并在下方堆叠一长页操作说明。
- 首页具有游戏启动画面的品质和明确主操作；关卡选择具有世界地图／冒险路线的视觉层级，但**不能展示尚未生产的关卡为真实可玩内容**。
- 道具以可识别的 Q 版图标、数字库存和简洁状态呈现；数字／触发条件仍来自权威 Runtime，不把不可用道具显示为可用。
- 奖励领取、踩雷、胜利、失败、道具使用应有清楚、温馨、短促的画面反馈。**先提交、后动画**；F5 不得重领，动画不得替代无障碍状态表达。
- 教程和帮助逐步移入教程关卡、指向性提示和按需帮助入口；不应占据常规对局的下半屏。若涉及教程完成条件或历史进度结构，必须先审查冻结合同影响。
- 必须提供真正适合 Q 版轻休闲体验的背景音乐与音效，去除令人不适的蜂鸣、粗糙碰撞音；音乐／音效开关独立生效，尊重自动播放策略和低动态效果设置。

## 7. 质量、范围与产品验收门禁

**技术上继续坚持：**单一生产 session、单一 guarded Save v4 writer，存档/领奖先提交后演出，严格区分生产内容与受控/兼容测试，保持 Stage 0–4 冻结和独立 Reviewer / PR / branch-main CI / Recovery 证据。

**产品上必须通过：**第一眼像可爱冒险游戏，1366×768 利用充分且布局简洁；动物可见地走在格子里、头顶显示唯一当前位置雷数；奖励与道具反馈被玩家看见而非隐藏在正文；背景音乐确实是音乐；中文清楚、语言入口显著；Home/Level/Game 三大页达到 Elio 的主观视觉最低线。

**需要守住的非目标：**当前不是批准重写 Mine RNG、奖励生成、存档版本、经济平衡、Benben 概率或上架 Steam；不为了图上好看而捏造钻石目标、体力系统、关卡数、已上线商品或不可执行图标。
