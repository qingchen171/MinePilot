# Product Manager Operation Manual v1.0

**状态：FROZEN**  
**读者：完全不需要懂编程的产品经理**

## 1. 你每天只做这件事

打开 `04_PROJECT_STATUS.md`，找到“唯一下一行动”，把对应标准指令交给 AI。不要同时布置第二件事。

工作闭环：**读状态 -> 发单一任务 -> 看 AI 计划 -> 允许执行 -> 看测试报告 -> 自己试玩 -> PASS 或报 Bug -> 更新状态 -> 才进入下一任务。**

## 2. 新会话标准开场指令

```text
请先完整读取以下五份控制文档，按权力顺序执行：
1) Minesweeper MVP Specification v1.0
2) AI Development Protocol v1.0
3) Product Manager Operation Manual v1.0
4) PROJECT_STATUS
5) Future Requirements Registry

先不要写代码。请告诉我：
- 当前 Stage / Task；
- 当前唯一下一行动；
- 本次任务的目标、非目标、风险、测试和回滚点；
- 是否存在文档冲突或信息不足。
```

如果 AI 没有先读文档、直接开始写代码：立即让它停止。

## 3. 每个 Task 的逐步 SOP

### 步骤 1：确认任务

你只检查三件事：任务 ID 是否与 PROJECT_STATUS 一致；是否只有一个目标；是否出现“顺便重构/顺便加功能”。有任何不一致就要求 AI 重写计划，不允许执行。

### 步骤 2：允许实现

```text
计划范围确认。只执行当前 Task，不做非目标内容。完成后按 AI Development Protocol 提交测试结果、人工验收步骤和回滚方法。未通过测试不得宣称完成。
```

### 步骤 3：看完成报告

你不需要读懂代码。确认 AI 明确列出：改了什么、没改什么、测试是否全绿、哪些风险还在、你要怎样试玩、如何回滚。

### 步骤 4：人工验收

严格按 AI 给出的步骤操作。额外遵守：

- 正常路径玩一遍。
- 故意点错/取消/刷新/退出再打开。
- 涉及移动端时，用至少一个手机尺寸体验误触和文字。
- 涉及存档/奖励/道具时，必须 F5 一次并检查是否复制或丢失。
- 不凭“看起来差不多”通过。

### 步骤 5A：通过

```text
我已按验收步骤完成试玩，结果 PASS。请只更新 PROJECT_STATUS：记录验收证据、稳定提交/版本点，并给出下一项唯一行动。不要开始下一项代码。
```

### 步骤 5B：失败

使用第 5 节 Bug 模板。修复后从步骤 3 重新开始，不能跳过复验。

## 4. 各阶段你要做什么

### Stage 0：工程骨架

你不评判技术细节；你确认 AI 能在 Windows 上重复完成：启动、构建、测试、查看版本、恢复到稳定点。通过条件是“换一个新 AI 读文档后也知道怎样运行”。

### Stage 1：核心棋盘

你试玩移动、单数字显示、已探索痕迹、旗帜、0 反馈、踩雷、胜利。不要要求商店、漂亮角色或音乐。

### Stage 2：状态与存档

你重点做 F5、关闭浏览器、继续游戏、主动重开、崩溃恢复。任何复制奖励、改变雷位、丢旗、道具复原都不通过。

### Stage 3：四大道具

一次只验一个道具。每个道具需单独 PASS；组合测试最后做。不要一次让 AI 同时实现四个。

### Stage 4：游戏循环

验收关卡选择、奖励、库存、商店、失败保留资产、笨笨援助和旧关重玩。

### Stage 5：表现层

你判断温柔/温馨/友好/可爱是否成立，动画是否拖沓、声音是否烦、奖励反馈是否开心。

### Stage 6：适配

你重点测手机误触、中英文切换、文字溢出、横竖视口、触控旗帜模式和测试主题。

### Stage 7：RC

你按完整回归清单玩 L1、L5、L10、最后一关；找身边测试者；只有没有 P0/P1 且已知 P2 有处置时才能发布候选。

## 5. Bug 报告模板

```text
Bug ID：BUG-YYYYMMDD-01
当前 Stage / Task：
严重级别：P0 / P1 / P2 / P3 / 不确定
设备：电脑/手机；系统；浏览器
游戏版本或 commit：
发生前我在做什么：
复现步骤：
1.
2.
3.
实际结果：
预期结果：
是否每次出现：总是/偶尔/只出现一次
刷新后是否还在：
是否可能丢存档/复制奖励：
截图或录屏：有/无

请先复现和做根因分析，不要直接试错修改。给出受影响范围、最小修复、测试和回滚方案后再执行。
```

严重级别：P0=存档/资产严重损坏、无法启动或安全问题；P1=核心流程无法完成或稳定复制资源；P2=重要功能错误但有绕过；P3=轻微显示/文案问题。

## 6. STOP 规则

出现任一情况，立即停止开发：

- 你不知道下一步是什么。
- AI 想跳过当前 Task、顺手重构或加新功能。
- 测试失败、构建失败、人工验收失败。
- 同一 Bug 修了两次仍失败。
- AI 无法解释影响范围或回滚方法。
- 规格与实现冲突。
- 存档、奖励或道具疑似复制/丢失。
- 需要花钱、购买服务、改变路线图、上线或公开发布。
- 需要删除/覆盖大量文件或做破坏性 Git 操作。

STOP 后使用：

```text
停止修改。不要写代码。请根据控制文档和当前证据，给我产品经理版根因分析：已知事实、假设、风险、可选方案、推荐方案、回滚点、需要我决定的问题。
```

## 7. 新想法处理

任何新创意只做记录：

```text
请把这个想法按 Future Requirements Registry 模板登记，评估价值、成本、依赖、风险和启用条件。不要修改当前 MVP 规格、代码或 PROJECT_STATUS。
```

只有版本规划时才能从 Registry 提升为候选；改变路线图必须由你确认。

## 8. 看不懂时怎么问

```text
我不理解这段技术解释。请不要修改代码，用产品经理能验证的语言说明：它解决什么问题、如果不做会怎样、我能看到什么、如何证明它有效、失败时怎样恢复。
```

永远不要因为“不好意思问”而猜。

## 9. 隔很久回来

```text
我刚回到项目。请读取五份控制文档和当前 Git/测试状态，不要写代码。告诉我项目最后一个稳定点、当前阻塞、未验证风险，以及现在唯一应该执行的下一步。
```

## 10. 你不需要做的事

不需要学会 TypeScript、修代码、选择架构或判断测试框架。你需要对体验、范围、验收与投入做决定，并坚持“一次一个任务、测试后试玩、通过才推进”。
